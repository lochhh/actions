# Start a Green DiSC review cycle

This action starts a review cycle in a repository created from the Green DiSC toolkit template. A cycle is the period leading up to one review meeting; its milestone's due date is the meeting date, chosen by the team.

It:

1. checks that whoever ran the workflow has the **Maintain** or **Admin** role, and stops otherwise;
2. creates the cycle's milestone (default name `Review-<year>-<month>` of the due date; spaces in a given name become hyphens, because GitHub's milestone links don't quote names);
3. creates a check-in for each owner of an open personal record, assigned to them, asking them to go over their record, the group record and the guides; the check-in of whoever started the review (the representative) also asks them to save the group record, review guide pull requests, check the README and hold the meeting, plus checking and merging the criteria sync pull request when `criteria-pr` is given, and links the criteria text for the tiers in `config.yml` (`tiers`, default `[Bronze]`);
4. closes the previous cycle: its open check-ins are closed, then its milestone is closed;
5. writes a summary to the job summary, including records with unsaved changes.

Check-ins are to-do lists. Lines for records the bot tracks end with a hidden `<!-- record:N -->` marker; when record N is saved, [`save_record`](../save_record/README.md) ticks them and closes the check-in once all tracked lines are ticked, unless it contains `<!-- keep-open -->`: the representative's check-in stays open until they close it after the meeting. The member's line about adding to the group record has no marker: it's a reminder, since most people will have nothing to add.

Running it again for the same cycle adds only what's missing, so a failed run can be re-run.

The workflow's inputs reach the script only through environment variables. `yq`, preinstalled on GitHub-hosted runners, converts `config.yml` and `criteria.yml` to JSON, so the script uses the standard library only.

## Inputs

| Input | Default | Description |
|---|---|---|
| `due` | (required) | Review date, as `YYYY-MM-DD`; the milestone's due date |
| `name` | `Review-<year>-<month>` | Cycle and milestone name |
| `criteria-pr` | (blank) | Number of an open criteria sync pull request; adds an item to the representative's check-in |
| `config` | `config.yml` | May set `tiers` |
| `criteria` | `criteria.yml` | Generated by [`sync_criteria`](../sync_criteria/README.md) |
| `token` | `github.token` | Token with `issues: write` |

## Examples of usage

The Green DiSC toolkit template ships a complete workflow (`.github/workflows/review.yml`); the core is:

```yaml
on:
  workflow_dispatch:
    inputs:
      due:
        description: Review meeting date (YYYY-MM-DD)
        required: true
      name:
        description: Cycle name (default Review-<year>-<month>)
        required: false

jobs:
  review:
    runs-on: ubuntu-latest
    permissions:
      contents: read
      issues: write
    steps:
      - uses: actions/checkout@<sha> # v7.0.1
      - uses: lochhh/actions/greendisc_toolkit/review_cycle@<sha>
        with:
          due: ${{ inputs.due }}
          name: ${{ inputs.name }}
```
