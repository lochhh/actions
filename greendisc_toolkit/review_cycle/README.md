# Start a Green DiSC review cycle

This action starts a review cycle in a repository created from the Green DiSC toolkit template. A cycle is the period leading up to one review meeting; its milestone's due date is the meeting date, chosen by the team.

It:

1. checks that whoever ran the workflow has the **Maintain** or **Admin** role, and stops otherwise;
2. creates the cycle's milestone (default name `Review <year>-<month>` of the due date);
3. creates one issue per criterion in `criteria.yml`, for the tiers listed in `config.yml` (`tiers`, default `[Bronze]`), labelled with the criterion's label and linking the previous cycle's issue for it (`- [ ] #12`);
4. creates a check-in for each owner of an open personal record, assigned to them, and one for the representative named in `config.yml`, which also asks them to check and save the group record;
5. closes the previous cycle: its open issues are closed with a pointer to their replacement, then its milestone is closed;
6. writes a summary to the job summary, including records with unsaved changes.

Check-ins are to-do lists. Lines for records the bot tracks end with a hidden `<!-- record:N -->` marker; when record N is saved, [`save_record`](../save_record/README.md) ticks them and closes the check-in once all tracked lines are ticked. The member's line about adding to the group record has no marker: it's a reminder, since most people will have nothing to add.

Running it again for the same cycle adds only what's missing, so a failed run can be re-run.

The workflow's inputs reach the script only through environment variables. `yq`, preinstalled on GitHub-hosted runners, converts `config.yml` and `criteria.yml` to JSON, so the script uses the standard library only.

## Inputs

| Input | Default | Description |
|---|---|---|
| `due` | (required) | Review date, as `YYYY-MM-DD`; the milestone's due date |
| `name` | `Review <year>-<month>` | Cycle and milestone name |
| `config` | `config.yml` | Must set `representative` (`name`, `github`, `contact`); may set `tiers` |
| `criteria` | `criteria.yml` | Generated by [`sync_criteria`](../sync_criteria/README.md) |
| `token` | `github.token` | Token with `issues: write` |

## Examples of usage

The Green DiSC toolkit template ships a complete workflow (`.github/workflows/review.yml`); the core is:

```yaml
on:
  workflow_dispatch:
    inputs:
      due:
        description: Review meeting date (YYYY-MM-DD)
        required: true
      name:
        description: Cycle name (default Review <year>-<month>)
        required: false

jobs:
  review:
    runs-on: ubuntu-latest
    permissions:
      contents: read
      issues: write
    steps:
      - uses: actions/checkout@<sha> # v7.0.1
      - uses: lochhh/actions/greendisc_toolkit/review_cycle@<sha>
        with:
          due: ${{ inputs.due }}
          name: ${{ inputs.name }}
```
